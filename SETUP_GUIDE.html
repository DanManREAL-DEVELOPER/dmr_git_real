GIT_REAL v1.2 · schema 2

Install once. Check the exact operation.

GIT_REAL reads repository metadata locally and returns preservation evidence for a supported Git operation. It does not execute the operation.

1. Clone

git clone https://github.com/DanManREAL-DEVELOPER/dmr_git_real.git
cd dmr_git_real

2. Install into an existing repository

python setup_gitreal.py "/absolute/path/to/your/project" --with-hook

Success requires the exact final receipt:

GIT_REAL_SETUP_PASS

3. Verify without changing the target

python setup_gitreal.py "/absolute/path/to/your/project" --check

Success requires:

GIT_REAL_CHECK_PASS

4. Read fresh state

python gitreal.py "/absolute/path/to/your/project" --quick --json
Require version == "1.2.0", schema_version == 2, the canonical root, read_complete == true, and an empty read_errors list.

5. Check a plain commit

python gitreal.py "/absolute/path/to/your/project"   --quick --json --operation commit_index

Commit only when the fresh requested_action names commit_index, has safe == true, and returns decision == "ALLOW".

Supported operation checks

  • commit_index — plain commit of the inspected index.
  • discard_tracked — restore tracked worktree files from the index.
  • clean_untracked — plain git clean -fd.
  • clean_ignored — plain git clean -fdx.
  • reset_hard --target <commit> — one explicit commit target.
  • drop_stash --target 'stash@{N}' — one selected stash.

Limits

  • A result is a snapshot, not a lock against later writers.
  • Local tracking refs are not live remote verification.
  • An ALLOW applies only to the exact operation and target returned.
  • GIT_REAL v1.2 does not inspect file contents for secrets.
  • Use dedicated backup, secret-scanning, and access-control systems too.

Read AGENT_SETUP.md, SECURITY.md, and PRIVACY.md before production use.
