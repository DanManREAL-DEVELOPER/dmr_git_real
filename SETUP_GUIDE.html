GIT_REAL v1.3.1 · schema 2

Install once. Check the exact operation.

GIT_REAL reads repository metadata locally and returns preservation evidence for a supported Git operation. It does not execute the operation.

1. Get the distribution

If you already have the intended download, use it. Otherwise, when obtaining this public distribution is in scope:

git clone https://github.com/DanManREAL-DEVELOPER/dmr_git_real.git
cd dmr_git_real

2. Install into an existing repository

python setup_gitreal.py "/absolute/path/to/your/project"

Use Python 3.10 or newer and an available Git executable. The installer copies two runtime files, adds the local output ignore line and wires agent instructions. Add --with-hook only when the selected setup includes a pre-commit hook. An existing custom hook location is preserved by refusing that option; an unmanaged hook is left unchanged and reported as skipped.

Success requires the exact final receipt:

GIT_REAL_SETUP_PASS

A different existing runtime requires authorized replacement with --replace; old files receive unique backups. Use --no-wire-agents to preserve instruction files. A later failure can leave a partial installation, so inspect its receipt and backups before resuming. --no-verify ends with GIT_REAL_SETUP_UNVERIFIED, not a verified success.

Optional: check an existing installation

A normal verified install already checks fresh runtime state; this is not a required second step. The mode performs no installer file writes, but executes the installed engine. It is not a sandbox for replacement runtime code, and it does not verify that a hook is active or an MCP client is connected.

python setup_gitreal.py "/absolute/path/to/your/project" --check

Success requires:

GIT_REAL_CHECK_PASS

3. Read fresh state when needed

python gitreal.py "/absolute/path/to/your/project" --quick --json
Require successful JSON object output, version == "1.3.1", integer schema_version == 2, the canonical root, is_repo == true, a nonempty publication_id, read_complete == true, and an empty read_errors list.

4. Assess a plain commit when it is in scope

python gitreal.py "/absolute/path/to/your/project" --quick --json --operation commit_index

Commit only when the fresh requested_action names commit_index, has safe == true, and returns decision == "ALLOW", and the operation is authorized. The verdict covers the inspected root, HEAD, index and publication identity. It does not cover commit-all, amend, path arguments or later changes. A valid BLOCK can accompany successful installation; setup success is not commit approval.

Examples of supported operation checks

  • commit_index — plain commit of the inspected index.
  • discard_tracked — restore tracked worktree files from the index.
  • clean_untracked — plain git clean -fd.
  • clean_ignored — plain git clean -fdx.
  • reset_hard --target "COMMIT_OID" — replace the placeholder with one explicit commit ID.
  • drop_stash --target 'stash@{N}' — one selected stash.

These are assessments, not execution commands. Other operation contracts are described in README.md. For an existing MCP client, is_safe_to_commit(path) returns the action fields directly; git_real_status(path) returns repository state. Use AGENT_SETUP.md for the interface differences.

Limits

  • A result is a snapshot, not a lock against later writers.
  • Local tracking refs are not live remote verification.
  • An ALLOW applies only to the exact operation and target returned.
  • GIT_REAL v1.3.1 does not inspect file contents for secrets.
  • Its receipts do not establish the absence of secrets or authorize a separate scan. Backup and access-control policies remain separate.
  • Incomplete evidence blocks the affected action. Continue independent authorized work and clarify only a consequential unresolved choice.
  • These local receipts do not establish release readiness or authorize publication. Setup does not register, restart or verify an MCP client.

For agent setup and closeout, use AGENT_SETUP.md and SKILL.md when that workflow is requested. Consult SECURITY.md and PRIVACY.md when those boundaries are relevant.
